Project Vision

Our vision starts with a simple problem: reading dense, 400-year-old theological texts is difficult, and it can be a very solitary experience. The CCEL website is an amazing resource, but it's currently a static collection of texts. Our vision is simple: "no one should have to feel lost or alone when reading a great book".

We want to transform CCEL into a living conversation. Our project does this by integrating two distinct AI-powered systems. This creates a twofold technical challenge:

  • Reader's Tools — "Explain" and "Modernize" contextual buttons that help readers understand difficult passages on-the-fly
  • Smart Library Assistant (Chatbot) — "Ask CCEL a question" conversational interface powered by an external Python service

By strictly integrating these features into the native CCEL environment, we aim to make profound theological study accessible to everyone, regardless of their academic background, creating a true "co-pilot" for digital reading.

Design Norms & Ethical Considerations

Transparency & Data Privacy

We provide clear visual indicators that chat data is processed by an external service (SLA) and ensure all AI content is labeled with source citations to prevent hallucinations.

Cultural Appropriateness

The AI acts as an inquisitive guide, not an expert, enhancing the studious atmosphere rather than disrupting it with flashy features.

Stewardship

We balance features with costs by using efficient models (Claude 3.5 Sonnet) and lazy loading for the chatbot to minimize expensive API calls.

Trust & Reliability

Implementing rate limiting (50-200 req/hr), input validation, health checks, and comprehensive monitoring to maintain user trust.

Security

API keys stored server-side, CSRF tokens, XSS prevention, prompt injection detection, and per-user rate limiting.

Accessibility

Responsive design, keyboard navigation, semantic HTML, and clear error messages for all users.

2. Complete Frontend Application (1500+ Lines)

Implemented reader-tools-integration.js with:

  • Persistent sidebar (500px fixed width, slides in from right)
  • Two tabs: Reader Tools (Explain/Modernize/Background) and Chatbot (conversational)

  • Session persistence with localStorage
  • Complete markdown-to-HTML converter with proper formatting
  • Error handling, loading states, and user feedback

3. Security Implementation

Comprehensive security measures:

  • API keys never exposed to client (server-side only)
  • Rate limiting per-user with configurable limits
  • Input validation and prompt injection detection
  • CSRF token protection on all forms
  • XSS prevention through HTML escaping

Created infrastructure monitoring:

  • Public status monitor dashboard with real-time color coding
  • Response time tracking and auto-refresh
  • Admin abuse monitoring capabilities

5. Zero Database Changes

All features implemented without modifying database schema. Stateless proxy design means no persistent storage of AI interactions.

Streaming Pipeline

Real-time responses using Server-Sent Events (SSE):

  1. Client sends request to PHP proxy endpoint
  2. PHP calls external API (Claude or SLA) with streaming enabled
  3. Server receives SSE chunks and parses line-by-line
  4. Converts SSE format to NDJSON (newline-delimited JSON)
  5. Sends streamed data to client with event-stream headers
  6. JavaScript accumulates raw text and renders markdown once complete
  7. User sees real-time typing effect with proper formatting

Key Technical Decisions

Server-Side Proxy Pattern

All API calls routed through PHP backend to keep keys secure, enable rate limiting, and provide abuse monitoring.

SSE to NDJSON Conversion

Chose NDJSON over raw SSE for easier client-side parsing and compatibility with different streaming sources.

Vanilla JavaScript (No Frameworks)

1500+ line pure JS implementation avoids large dependencies and keeps bundle size minimal.

Laravel Cache for Rate Limiting

Leveraged existing Laravel infrastructure (Redis/file-based) for fast, distributed rate limit tracking.

Purple Gradient Theme

Consistent visual branding across all UI elements (#667eea to #764ba2) for cohesive user experience.

Rate Limiting Strategy

Reader Tools

Limit: 200 requests/hour per user

Rationale: Lower frequency, quick processing (explain/modernize)

Chatbot

Limit: 50 requests/hour per user

Rationale: Conversational nature; prevents abuse of expensive API calls

User Identification: Priority order — Authenticated user ID → Session ID → Anonymous (IP-based)

Storage: Laravel Cache system (Redis in production, file-based in development)

Response: HTTP 429 with Retry-After header when exceeded

Rate Limiting Implementation

// In ReaderToolsProxyController.php
public function checkRateLimit($service) {
    $userId = Auth::check() ? Auth::id() : 
              (session()->getId() ?: request()->ip());
    
    $limit = $service === 'chatbot' ? 50 : 200;
    $key = "rate_limit:{$service}:{$userId}";
    
    $current = Cache::get($key, 0);
    if ($current >= $limit) {
        return response()->json(
            ['error' => 'Rate limit exceeded'],
            429
        )->header('Retry-After', '3600');
    }
    
    Cache::put($key, $current + 1, now()->addHour());
}

Server-Sent Events Streaming

// Stream Claude response as NDJSON
private function streamClaudeResponse($stream) {
    $allRawText = '';
    
    foreach ($stream->getIterator() as $chunk) {
        $lines = explode("\n", $chunk);
        
        foreach ($lines as $line) {
            $parsed = $this->parseSSEChunk($line);
            if ($parsed) {
                $allRawText .= $parsed['text'];
                echo json_encode([
                    'type' => 'chunk',
                    'text' => $parsed['text']
                ]) . "\n";
            }
        }
    }
    
    // Emit complete event
    echo json_encode([
        'type' => 'complete',
        'fullText' => $allRawText
    ]) . "\n";
}

Security: Prompt Injection Detection

// Detect suspicious patterns
private function containsSuspiciousPatterns($input) {
    $patterns = [
        '/system\s*prompt/i',
        '/ignore.*instructions/i',
        '/forget.*previous/i',
        '/execute.*code/i',
        '/\{.*\{.*\}/i',  // Nested braces
    ];
    
    foreach ($patterns as $pattern) {
        if (preg_match($pattern, $input)) {
            Log::warning('Suspicious pattern detected', 
                ['input' => substr($input, 0, 100)]);
            return true;
        }
    }
    
    return false;
}
